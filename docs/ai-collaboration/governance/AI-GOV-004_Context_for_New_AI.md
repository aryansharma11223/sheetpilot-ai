# Purpose

This document provides the essential background knowledge required for an AI joining the AEVON project for the first time.

Its purpose is to establish a shared understanding of the project's vision, architecture, engineering philosophy, and repository organization before any engineering work begins.

This document is intended to reduce onboarding time while preserving consistency across engineering sessions and AI platforms.

---

# Scope

This document defines:

- What AEVON is.
- Why AEVON exists.
- The project's long-term vision.
- High-level repository organization.
- Engineering philosophy.
- Documentation philosophy.
- Core architectural concepts.
- Technologies used throughout the project.

This document does not define the current project state, active milestone, engineering tasks, or migration procedures.

---

# What is AEVON?

AEVON is an AI Software Engineering platform designed to collaborate with human engineers throughout the software development lifecycle.

Its objective is to understand software systems, reason about engineering problems, assist in designing solutions, implement approved changes, verify outcomes, maintain documentation, and preserve engineering knowledge.

AEVON is designed to augment human engineering rather than replace it.

---

# Vision

The long-term vision of AEVON is to become a trustworthy AI engineering partner capable of contributing to complex software projects through structured reasoning, disciplined collaboration, and continuous learning.

Every capability developed within AEVON shall support this vision.

---

# Engineering Philosophy

AEVON follows a disciplined engineering approach built upon:

- Clear responsibilities.
- Structured reasoning.
- Modular architecture.
- Human oversight.
- Incremental improvement.
- Documentation-driven engineering.
- Long-term maintainability.

Engineering decisions are expected to be transparent, explainable, and traceable.

---

# Repository Overview

The AEVON repository is organized into logical areas that separate implementation, documentation, and supporting assets.

Typical repository areas include:

- Backend
- Frontend
- Documentation
- Configuration
- Development resources

Each directory is expected to have a clearly defined responsibility.

---

# Documentation Structure

Documentation is organized according to responsibility rather than file type.

Each document exists to answer one primary engineering question.

Documentation should remain:

- Focused.
- Maintainable.
- Non-overlapping.
- Easy to navigate.
- Valuable throughout the lifecycle of the project.

---

# Core Architecture

AEVON is designed as a modular system where individual components have clearly defined responsibilities.

Major architectural goals include:

- Separation of concerns.
- Replaceable components.
- Clear interfaces.
- Independent evolution.
- Scalable engineering practices.

---

# Technology Stack

AEVON may incorporate multiple technologies depending on engineering requirements.

Examples include:

- Python
- TypeScript
- Web technologies
- AI models and providers
- Supporting engineering tools

Implementation technologies may evolve while preserving the architectural principles defined by the project.

# Key Terminology

Throughout AEVON, common terminology includes:

- Milestone

- Context
- Architecture
- Verification
- Documentation

Understanding these concepts is essential for effective collaboration.

# Expectations for a New AI

A newly onboarded AI is expected to:

- Understand the purpose of AEVON.
- Follow the established governance.
- Respect project architecture.
- Collaborate professionally with the Human Engineer.
- Seek clarification whenever necessary.
- Contribute consistently within approved responsibilities.
