# Purpose

This document defines the standard procedure for transferring the AEVON engineering collaboration to a different AI platform, AI account, repository, computer, or engineering environment.

Its purpose is to preserve engineering continuity while minimizing the loss of project knowledge, context, and governance.

---

# Scope

This document defines:

- When migration is required.
- Migration preparation.
- Required project information.
- Governance transfer.
- Context transfer.
- Validation after migration.
- Migration completion.

This document does not define engineering tasks, project state, or collaboration rules.

---

# When Migration is Required

Migration should be performed whenever engineering work must continue in a different environment.

Examples include:

- New AI platform.
- New AI account.
- New computer.
- New repository.
- New engineering environment.
- Long-term project archival and restoration.

---

# Migration Preparation

Before migration begins:

- Complete the current engineering task whenever practical.
- Update all required governance documents.
- Ensure repository changes are committed.
- Verify documentation is synchronized with implementation.
- Record any outstanding blockers.

Migration should begin only after the project accurately reflects its current state.

---

# Required Information

The following information shall accompany every migration:

- AI Collaboration Governance package.
- Current project documentation.
- Repository.
- Engineering decisions.
- Technical debt.
- Current project state.
- Next engineering task.

The receiving environment should be capable of reconstructing the engineering context from these artifacts.

---

# Migration Procedure

Perform migration using the following sequence:

1. Prepare the project.
2. Transfer the repository.
3. Transfer documentation.
4. Transfer governance documents.
5. Verify project integrity.
6. Validate engineering context.
7. Resume engineering work.

Each step should be completed before proceeding to the next.

---

# Validation

After migration, verify that:

- Governance documents are available.
- Repository structure is intact.
- Documentation is complete.
- Current State reflects the latest project status.
- Next Task identifies the correct engineering objective.
- No engineering knowledge has been lost.

Any inconsistencies should be resolved before continuing development.

---

# Completion Criteria

Migration is complete when:

- The receiving AI understands the project.
- Governance has been reviewed.
- Project context has been restored.
- Repository integrity has been verified.
- Engineering work can resume without reconstructing previous discussions.

---

# Maintenance

Review this document whenever the project's migration process changes.

Keep the migration procedure simple, repeatable, and independent of any specific AI platform or tooling.
